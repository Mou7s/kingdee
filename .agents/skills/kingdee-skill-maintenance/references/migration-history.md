# 技能维护（拆分 / 索引 / 纳管）

针对 `.agents/skills/<id>/` 的维护：把过大的 `SKILL.md` 瘦身、把没人引用的 reference 补进索引、把技能资产纳入 git。仅搬移章节时逐字节保留并校验；用户授权标准化改写时按职责重写入口，保留领域不变量与案例证据，并记录对应去向。不要在重构中顺手删除业务证据。

## 触发

- 某 `SKILL.md` 过大（实测 187KB 会把整个正文塞进上下文，加载成本极高）
- reference 存在但没有入口引用，难以在需要时被发现
- 技能资产还在工作区、未进 git

## 一、先保留原始版（做还原点，务必第一步）

已获提交授权时：

```bash
git add .agents/skills/<id>
git commit -m "chore(skills): bring <id> under version control"
git log --oneline -1   # 记下这个 commit hash 作为校验基准
```

已有未提交修改或用户只要求本地整理时，可先把本次将修改的文件逐字节备份到 `output/`，记录路径与哈希作为基准；不要为建立还原点擅自提交其他工作。已获提交授权时，`git show <commit>:<path>` 可作为校验基准。

## 二、机械拆分 SKILL.md（零丢失）

只按行首 `^## ` 切块，不碰块内文本：

```js
const chunks = text.split(/(?=^## )/m); // [0]=frontmatter+前言，其余每块以 "## " 开头
```

- **保留块**留在正文：`When to use` / `Source of truth` / `Connectivity` / `Runtime` / `Hard rules` / `输出语言` / 状态码表 / `References` 索引等触发条件与环境约定。
- **其余大块**（一般 ≥ 700 字节、且不属于核心约定）写成 `references/playbook/<slug>.md`：把首行 `## X` 升为 `# X`，其余原样。
- 匹配标题用**唯一子串 `includes`**（标题常含全角括号/引号，别照抄整串）。
- 正文尾部追加索引：`- \`references/playbook/<slug>.md\` — <原章节标题>（原 SKILL.md 章节全文）`。

## 三、逐字节校验（必须）

- 基准取纳管 commit：`git show <commit>:<path>`；本地整理则读取第一步逐字节备份，并核对记录的哈希。
- 断言 ①：每个搬出文件的正文（`# ` 降回 `## `）与原始块**逐字节相等**；
- 断言 ②：新正文 == 所有保留块按原顺序拼接。
- **行尾归一化**再比：工作区常是 CRLF、git blob 是 LF，不归一化会全报 MISMATCH（`s.replace(/\r\n/g,"\n")`）。
- 打印计数自证真的跑了：`抽出 N 个，不一致 0；正文拼接一致 是`。

## 四、孤儿扫描 + 补索引

- 扫描所有 `references/**/*.md`，逐个检查 `SKILL.md` 是否含完整的 `references/.../文件.md` 路径，并核对目标存在。不得仅匹配文件名：不同目录的同名文件会掩盖漏索引。
- 孤儿本质是「发现不了」，默认**补进索引**，不要删。按用户已授权的维护范围补入口，保留原文件和业务内容；仅删除或改变业务含义时另行确认。
- 补录后重扫一次，孤儿数应为 0。

## 五、收尾

```bash
bun run test:safety      # 全部通过
git diff --check         # 无空白错误（LF/CRLF 提示可忽略）
```

仅在用户授权提交时执行提交；说明还原基准，且不擅自 push。

## 六、合规审计（一键门禁）

```bash
bun scripts/tools/audit_skills.js .agents/skills/<id>
```

exit 0 = 通过。检查项：正文 ≤500 行、名称为 ≤64 字符 kebab-case 且与目录一致、`description` ≤1024 且非空、路径全正斜杠、>100 行的 reference 有目录、引用路径存在、每个 reference 从 `SKILL.md` 以完整路径一层可达（不能仅匹配同名文件）。**不通过就不要提交。**

## 坑

- **行尾**：git 提交 LF、工作区 CRLF，校验前必须归一化，否则 25/25 全报 MISMATCH。
- **标题匹配**：含全角括号/引号的标题用唯一子串 `includes`，不要精确照抄。
- **先保留原始版再整理**：使用已授权的纳管提交或逐字节本地快照，不覆盖已有未提交工作。
- **搬运与改写分开验证**：纯搬移块须逐字节一致；授权改写时检查适用条件、关键不变量和原文去向，不把重写结果宣称为逐字节搬移。
- **正文里的相对引用**：技能内自用路径相对 `SKILL.md` 目录，业务脚本写 `scripts/tools/...`（仓库根）——两种 `scripts/` 含义不同，移动章节后检查是否断链（`见下/同上/本文件`）。
- **公共安全基线**：本仓库 `main` 曾做过 `prepare public-safe toolkit` 清洗；把完整内网内容提交/推送到 `main` 前必须向用户确认仓库私有性与影响。

### 审计回归验证

运行 `bun test ./scripts/tests/audit_skills.test.js`。覆盖合法技能、缺失/空描述、名称格式及目录不一致、错误路径、同名参考文件漏索引和无二级标题的长参考文件。审计只确认这些结构要求，不证明业务事实正确，也不替代真实数据回查。

## 标准化设计与行为复核

- `AGENTS.md` 放全仓库始终生效的规则；`SKILL.md` 放能力、完成条件与条件阅读入口；references 放领域流程、字段与案例；稳定工具放仓库 `scripts/tools/`。
- 不复制通用教程、不强制普通任务加载所有资源；参考条目说明适用条件。命名和描述只用于准确发现，具体风险边界写在正文/参考。
- 一层直达、500 行上限和长文档目录是本仓库约定，不是全部技能的通用格式要求。
- 整理时检查原文到新位置的对应关系；历史数字须有验证日期或明确日期未知。原有案例保留，重复的通用规则引用唯一依据。
- 结构审计后用真实任务场景检查选路：连接只读取数；建料读取范围和模板；跨月对账区分 AP 类型；客户解冻不扩展字段；写入失败停止；只读问题不执行写入。这是本地人工复核，不宣称实际操作过生产账套。
- 金蝶业务流程由 `kingdee-k3cloud` 负责；技能整理、引用修复与审计由本技能负责。普通业务任务不需要加载本维护技能。

## 内容治理与工具验证

同主题流程只维护一份现行入口；旧摘录标历史并指向现行流程，独特约束先核对再迁移，案例不得充当默认写入规则。变更文件位置同步核对 SKILL.md、全部 references 和仓库文档的调用路径。辅助脚本验证运行 `bun test ./scripts/tests/skill_helpers.test.js ./scripts/tests/audit_skills.test.js`；补丁提取用本地 CAB 成功/失败样例验证退出码及源文件哈希，文档转换核对内容与实际依赖，交付文档另外做布局检查。

整理完成后评估 output 伴随产物时，先只读清点，再以 SHA256 核对重复内容，并扫描脚本、技能及输出脚本中的引用；静态扫描无引用不能排除动态拼接路径，内容相同也不能视为路径可互换。业务操作前后快照、恢复依据和最终报告默认保留；重复业务证据须先选定保留副本并处理引用关系。

`.xlsx.inspect.ndjson` 仅在对应工作簿仍存在且确认内容为可再生成的检查输出时列为可删；原工作簿缺失时先保留。临时应用配置须确认无在用进程；迁移前备份在改动未提交或未验收时保留。判断与实际删除分开，用户只要求评估时交付逐文件清单，不执行删除。2026-10-17 本地审计工具：`scripts/scratch/2026-10/audit-output-cleanup.mjs`，证据见 `output/cleanup-assessment-20261017.json`；统计是当次快照，复用前重扫。
