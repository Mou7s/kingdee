# 金蝶社区文档读取与取证

整理日期：2026-10-13。依据：旧 SKILL.md 的 SSR 提示及同技能 `../kingdee-system-admin/references/system/version-and-patch-inventory.md` 第 5 节历史取证。此次只整理本地方法，未重新验证社区页面结构；不是从缺失的外部技能复制的已验证完整实现。

## 读取顺序

1. 先用当前可用的网页读取工具打开用户给出的文章，核对标题、文章 ID、正文和发布日期。只有占位或正文缺失时才转原始 HTML。
2. 使用 `curl.exe -L -A "Mozilla/5.0" --output <本地输出文件> <文章URL>` 获取原始 HTML，记录来源 URL、获取时间和响应状态，文件放 `output/`。URL 作为独立参数传递，不拼成可执行 shell 文本；遇到登录或访问限制如实说明。
3. 历史记录中的候选参数为 `productLineId=1&isKnowledge=2&lang=zh-CN`。保留原查询参数，只补缺失项；响应很大不等于有正文，必须搜索标题及业务关键词核对。
4. 历史页面曾在 `<meta name="知识详情">` 与 `window.__NUXT__` 中保存内容。先检查当前 HTML 是否仍存在这些结构，再用 HTML 解析器取属性或文本。按实际编码层数解码 HTML 实体（旧记录曾需两次），每次检查结果；JSON 转义按 JSON 字符串规则处理，不反复全局替换，不使用 `eval`，不执行网页脚本。
5. payload 可能包含关联文章的完整正文。逐篇核对文章 ID、URL、标题与日期，不能把关联内容当成用户指定文章。历史 `\u002F` 转义是查找 URL 的线索，不是通用解析器。
6. 正文中的步骤可能只在插图里。以文章 URL 解析相对图片地址（历史形态为 `/download/<hash>.png`），用可用的图片查看工具核对按钮、字段和页面层级；文字读取失败时不能凭经验补写步骤。

## 结果核对

交付时给出支持结论的文章链接，说明是否已核对正文、截图和关联文章。无正文、无法查看插图或页面结构变化时，分别列明限制；不把历史方法的存在当成当前抓取成功。
