## 字段灰掉 / 审核后仍可改：先定位是哪一层锁的，再动手

**锁定有四层，厂商图文与多数网文只讲第一层；照抄它指路会白跑一趟**（本会话即如此：按网文让用户点「状态列表 → 已审核 → 字段控制」，那一行本来就**没勾**）。先只读元数据定位，再给用户步骤。

| 层 | 位置（BOS 设计器） | 管什么 |
|---|---|---|
| ① 状态列表的字段控制 | 「单据状态」字段属性 →「状态列表」→ 点中某状态（Z/A/B/C/D）→ 下方「字段控制」页签 → 该字段的「字段锁定」 | 该状态下能否编辑；默认常把已审核全锁死，但**不必然** |
| ② 实体服务规则 | 单据头 / 单据体的「实体服务规则」集合里 `锁定字段`(ActionId 8) / `解锁字段`(ActionId 26) 服务 | 条件成立时锁/解锁；**下推携带类锁定通常在②** |
| ③ 字段自身「锁定性」 | 字段属性 →「锁定性」 | 新增锁定 / 修改锁定 |
| ④ 单据类型字段属性 | 单据类型 → 布局（新增时不可维护 / 修改时不可维护） | 在 BOS 设置上再收紧（只收不放） |

只读定位（元数据在 `T_META_OBJECTTYPE`，`FID` 就是表单标识，**该表没有 `FNUMBER`/`FNAME`/`FFORMID`/`FTYPE`**）：

```sql
SELECT FID, FBASEOBJECTID, FINHERITPATH, FDEVTYPE, LEN(CAST(FKERNELXML AS NVARCHAR(MAX))) AS XMLLEN
FROM T_META_OBJECTTYPE WHERE FID='SAL_OUTSTOCK' OR FBASEOBJECTID='SAL_OUTSTOCK' ORDER BY XMLLEN DESC;
```

取 `CAST(FKERNELXML AS NVARCHAR(MAX))` 后在 JS 里按关键字切片（只打命中处前后几百字符，整份几十万字符不要输出）：

- ① `<StatusItem action=...>` → `<FieldControlItem><FieldKey>Fxxx</FieldKey><IsControl>False</IsControl>`；带 `<OperationerKey>FApproverID` 的那条就是「已审核」，`IsControl=False` = 不锁定。
- ② `<EntityServiceRule>` 块 → 读 `<Description>` / `<PreCondition>`，以及 `<WhenTrueBusinessServices>` 里的 `<ActionId>8</ActionId>`（锁定字段）/ `26`（解锁字段）和它锁的字段标识（`<Parameters>`）。
- 字段三元组：`<Key>` = 字段标识、`<PropertyName>` = View 键、`<FieldName>` = 物理列、`<EntityKey>` = 所属实体。

（`mssql.query(sql, [params])` 传参会报 `Must declare the scalar variable`，要用 `new mssql.Request().input(...)`；库内查到的 GUID 可直接内联拼接。）

改动只能在**扩展单据**里做（改不动就说明要签出基础对象）；改的是账套元数据、对全部用户生效，标准产品元数据还可能被升级补丁覆盖——先讲清代价，并优先给用户「只改这一张单就反审核→改→重新提交审核」的选项。

## 状态锁定性（第 ① 层）的步骤

1. 有 BOS 权限的账号登录**金蝶云星空集成开发平台（BOSIDE）**（独立客户端，一般装在实施/IT 机器上）。
2. 进入对应子系统（如 `供应链 > 销售管理`），找到目标单据：未扩展过先右键「扩展」；**已有自定义字段的标准单据（本账套如销售出库单带 `F_UNW_*`/`F_KD_*`）说明早已扩展，直接双击打开改，不要再扩展一次**。
3. `编辑 > 批量编辑字段属性` → 选中「单据状态」字段 → 打开其「状态列表」属性。
4. 在状态列表里点中「已审核」行 → 下方「字段控制」页签 → 找到目标字段（注意区分**单据头**与**单据体**下的同名字段）→ 取消「字段锁定」。
5. 保存（Ctrl+S），有「发布」提示就发布；**关闭并重新打开单据**（元数据重载）后生效。
6. 前台效果：已审核单据可点「修改」改该字段并直接「保存」，**单据状态保持「已审核」，不需要反审核**。

边界（必须先讲清）：

- 只对**无业务校验的自由文本/说明字段**可靠（备注、车号、实际称重…）。数量、单价、金额、物料、客户、仓库这类前后关联字段即使取消锁定，服务端插件仍会拦或改出账实不符——不要顺手放开。
- 改的是**账套元数据**，对该单据所有用户、所有记录生效；生产账套先在一张单上验证。
- **启用了工作流/审批流的单据，节点属性里还有一份字段锁定设置**，要一并核对；工作流场景下还需用户有对应权限。
- 同一张单可能有多个状态字段（单据状态 / 关闭状态 / 作废状态），各有独立状态列表，都要检查。
- 备选路径只有「反审核 → 改 → 保存 → 提交 → 审核」。但它不是默认答案：**已下推下游的单常被拒**（如销售出库分录 `RowARStatus='C'`、`SumInvoicedQty` 已满，反审核报「已有下游单据关联，不允许反审核」）。长期要反复改的字段才走元数据放开，且**先按上面的只读查询确认是哪一层在锁**——锁定来自②时，改①不会有任何效果。
- 回复「某个字段怎么设置才能审核后改」时：给「机制 + 入口步骤 + 边界 + 备选路径」，末尾问一句是否要按截图一步步带；不要只答「反审核后再改」。

### 案例：销售出库单「明细备注」灰掉，不是状态列表锁的（实测）

- 明细备注 = **`FEntrynote`**（`EntityKey=FENTITY`、物理列 `T_SAL_OUTSTOCKENTRY.FNOTE`、`PropertyName=Note`）；表头备注 = `FNote`（物理列 `T_SAL_OUTSTOCK.FNOTE`）。两者 `View` 里都叫 `Note`。
- 元数据里「审核中」「已审核」两个状态项对 `FEntrynote` 都是 `IsControl=False`（**没锁**）——用户在「状态列表 → 已审核 → 字段控制」看到那一行本来就没勾，白跑一趟。
- 真正锁它的是**单据体的实体服务规则**：描述「携带销售订单、发货通知单非空备注到出库单，则锁定出库单备注字段」，条件 `ISDRAW()=1 AND (FSrcType='SAL_SaleOrder' OR FSrcType='SAL_DELIVERYNOTICE') AND FEntrynote<>' ' AND FEntrynote<>''`，成立时 `ActionId 8 锁定字段(备注)` 参数 `FEntrynote`，不成立时 `ActionId 26 解锁字段`。
- 结论：**从上游下推且备注非空的销售出库单，备注一律灰掉，与是否已审核无关**（反审核到 `D` 也照样灰）。要放开只能在扩展/签出基础对象后删或改这条规则；先讲清「放弃备注与上游一致的防呆」这一代价，并优先给「只改这一张单」的路径。

指路规矩（本会话被用户当场纠正）：**先读元数据定位是哪一层，再给步骤**；一次只给一个动作、等用户回截图再给下一步；步骤要带可核对锚点——属性名 + 值形态（「状态列表」的值显示为 `(Collection)`）+ 字段标识 + **当前必须选中哪个对象**（不选中「单据状态」字段就没有「状态列表」属性；状态列表里不先点中某状态行，下方「字段控制」就是空的，用户会以为「没有」）。用户说「没有啊」时先看他的截图/问清他看到什么，不要重复念同一步。

## 「不符合条件不给保存」= 给操作挂校验规则（单据合法性校验）

**校验规则挂在「操作」上，不在字段上**（基础资料与单据同理）：

1. `批量编辑字段属性` → 左侧点 **`表单属性`** → 右侧点 **`操作列表`**(Collection)。
2. 在操作列表里搜到目标操作（如 **`保存`** / `Save`）→ 选中 → 点右侧 **「修改」**。
3. 操作编辑窗口 → **「其他控制」**页签 → **「校验规则」** → **「新增」** → 选服务 **「单据合法性校验」**。
4. 填 **校验表达式** + **提示信息** + **「校验表达式为真时提示」**，确定后保存设计器、重开客户端验证。

**勾选语义**（最容易搞反）：勾上 = 表达式为真时报错阻止；不勾 = 表达式为假时报错阻止。惯用写法是「表达式写允许条件 + 不勾」。

例：客户简称必须 0 开头 —— 表达式 `LEFT(FShortName,1) = '0'`（等价 `FShortName like '0%'`）、提示「客户简称必须以 0 开头」、**不勾**「为真时提示」。

- 表达式用**字段标识**（客户简称 = `FShortName`），标识取值先按元数据 `<Key>` 或 `executeBillQuery` 核实，不要按界面标题推。`LEFT/RIGHT/MID/LEN/ISNULL` 与 `like` 均可用。
- **空值会落进「不满足」分支**：要允许留空就写成 `ISNULL(FShortName,'') = '' OR LEFT(FShortName,1) = '0'`。

**上线前必须先量化影响面**（回答这类需求时主动做，不要等用户问）：

- 校验挂在 `保存` 操作上 → **新增和修改都拦**；前端手工、WebAPI `Save`、本仓库批量脚本与第三方同步一律被拦（会打断已有的批量改名/同步作业）。先跑只读统计存量影响面，例：本账套客户（审核状态）1019 家，其中 875 家简称以 `0` 开头、**144 家不是**——规则一生效，这 144 家以后改任何字段保存都会被拦。客户简称另有外贸 `-W` 后缀批次的存量，属同一批受影响对象。
- **标准产品没有「只校验新增」的开关**：要精确只拦新增只能写插件（`BeforeSave` 里判断 `this.View.OpenParameter.Status == OperationStatus.ADDNEW`），这属二开范围；否则先清理存量再上规则。
- 回退方式：删掉该条校验规则即可；优先加在扩展里，并先在测试账套拿一条验证（填违规值报错、填合规值能存）。

## 如何确定用户截图里的某一列是哪个字段（界面列 ↔ 字段标识）

**不要相信 vision/OCR 读出的表头文字来定案**——同一张 K3 界面截图，vision 两次给出不同列名（把宽列中间的标题错位、漏读），据此下结论必错。可靠三步：

1. 按截图里的单号 `executeBillQuery` 取 `FID`，再 `viewBill` 打印**表头与分录的全部键**（`Object.keys`）与**每行的非空值**。
2. 用 `RapidOCR`（`python` 环境已装 `rapidocr_onnxruntime` + `cv2`）跑整图，输出每段文字 box 的左上坐标 → 表头行按 y 聚集，得到各列标题与 x 坐标。
3. 定位列区间：取表头行的主色，找与该色差 >25 的**单像素竖线**即列分隔线；把 OCR 出的值坐标与区间对齐。K3 宽列表头文字可能居中、数据值左对齐，**所以「值在哪一列」只看值的 x 落在哪个区间，不要用列头文字位置或列序推**。

硬判据：**物理列的取值与截图那一列逐行对得上**——把分录表整行取回来（`SELECT *` 后在 JS 里逐列扫值，不要一列一条查询），看哪个列的值等于截图里的值。**不要用 `View` 的键反推字段标识**：`View` 的键是元数据的 `<PropertyName>`，同一表单的表头与分录可以共用同一个 `PropertyName`（如 `Note`），到底是 `FNote` 还是 `FEntrynote` 只能读元数据 `<Key>` 定案。另外 `View` 的值可能落后于库（截图发生在修改前、或字段是下推携带值），**以物理列 + 元数据为准**；`executeBillQuery` 的 FieldKeys 用字段标识且带 `F` 前缀，与 `View` 的键两套不通用。

### 本账套销售出库单（`SAL_OUTSTOCK`）字段实况（2026-09-18 实测）
- 表头备注 `FNote`（物理列 `T_SAL_OUTSTOCK.FNOTE`）与分录备注 `FEntrynote`（`PropertyName=Note`、`EntityKey=FENTITY`、物理列 `T_SAL_OUTSTOCKENTRY.FNOTE`）**共用同一个 `PropertyName`**，所以 `View` 里两处都叫 `Note`：回复「哪个备注」必须指明是单据体那个（字段标识 `FEntrynote`），别改错。
- 分录（`SAL_OUTSTOCKENTRY`）实测键：`Seq/MaterialID/UnitID/MustQty/RealQty/StockID/StockLocID/Lot/Lot_Text/Note/SoorDerno/SrcBillNo/SOEntryId/MTO NO 等`，价格在 `Price/TaxPrice/Amount/AllAmount`，下推状态在 `RowARStatus/SumInvoicedQty/ARJoinQty`。
- 该单据**已扩展**：表头自定义 `F_UNW_PrintTimes_qtr`(打印次数)、`F_UNW_Qty_83g`、`F_KD_price`、`FGYDATE`、`FSALECHANNEL`、`LogisticsNos`；分录自定义 `F_UNW_Text_83g`、`F_UNW_Text_o54`、`F_UNW_Picture_tzk`。界面上的「快递单号/客户订单号」等列可能就是这些自定义字段（标题可自定义，不能按标识推标题）。
