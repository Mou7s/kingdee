# 主管角色与客户数据范围排查

## 适用场景

用户说“客户基础资料已经设置只看自己，但某销售账号在应收/报表中仍能看到其他客户”，尤其是账号同时拥有销售员、销售主管或销售管理员角色时使用。

## 已验证的通用判断

1. **主管规则可能是有意放宽范围的规则**。规则名称如“销售管理员（可看所属组客户）”不等于“只看本人”。规则界面常把销售组、销售员、跟单员1、跟单员用“或者”连接；任一字段匹配即可看到客户。销售组条件会包含同组其他销售员的客户。
2. **客户基础资料规则默认不是所有单据/报表的全局过滤器**。金蝶官方手册说明数据规则默认只对单一业务对象有效；客户资料规则通常首先影响客户主档和业务单据新增时的 F8。只有启用“基础资料数据范围联动应用到业务对象”，并明确配置客户对应的业务对象和受控字段，才会联动到相应单据。
3. **报表要单独核查**。即使销售订单通过基础资料联动或内置业务员隔离看起来正常，也不能推断应收单或应收报表受同样控制。报表还要检查“报表的基础资料数据权限由报表本身的基础资料数据范围控制”以及报表客户映射。
4. **多角色按并集排查**。同一用户只要有一个对目标对象授予查看、但 `FDATARULE` 为空的有效角色，就可能放大数据范围。个人角色上的“只看自己”不能抵消主管角色的无规则查看权限。

## 推荐只读证据链

针对目标用户，逐层核对：

- 用户记录：账号、用户 ID、员工/业务员关联、禁用状态；
- 全部角色：角色名称、角色状态，不要只查“个人”角色；
- 目标对象：至少分别检查 `BD_Customer`、`SAL_SaleOrder`、`AR_RECEIVEBILL` 和实际报表对象；
- 查看权限：`T_SEC_FUNCPERMISSION`、`T_SEC_FUNCPERMISSIONENTRY` 中的查看权限和 `FDATARULE`；
- 规则定义：`T_SEC_DATARULE` / `T_SEC_DATARULE_L` 的 `FOBJECTTYPEID`、名称及 `FXML`，重点解析 `FilterString` 和 OR/AND 关系；
- 报表联动：`T_BAS_RPTDATARULECONFIG` 中是否有目标报表与 `BD_Customer` 的映射；
- 实际样本：客户主数据的 `FSELLER`、`FSALGROUPID`、跟单字段，与截图中的其他客户逐条比对。

## 本地账套中的核查经验

- 2026-10-13 沈君梅 TK00012 实时复查：销售员分录129180的销售组从 `T_BD_OPERATORDETAILS.FENTRYID` 关联 `FOPERATORGROUPID` 到 `T_BD_OPERATORGROUPENTRY_L.FENTRYID`；成员为营销一部、营销二部、营销三部、国际一部、营销五部（默认）。客户上的单一FSALGROUPID不等于账号销售组集合；默认营销五部不能据此推断只看五部。该用户当前主管规则使用FSALGROUPID的动态比较119（当前销售员所属组）并与销售员/跟单条件OR合并，汇报应写具体组集合加本人负责客户。规则XML中FilterString曾保存登录用户管理员A及深圳创科的展开值，不能把该快照当成沈君梅的实际组；须结合FilterSetting动态条件及业务员关联核验。此为当日配置，未逐账号登录验证，复用前重查。

- 主管角色的客户规则 `XSGLY` 绑定到业务对象 `BD_Customer`，其规则名为“销售管理员（可看所属组客户）”；实际 XML 中可见销售组、销售员和两个跟单字段以 OR 连接。
- 该规则示例包含销售组 `深圳创科`；该组客户中可以存在销售员为其他人的客户，因此看到同组客户并不代表客户主数据的销售员归属被改错。
- 同一用户的 `AR_RECEIVEBILL` 可能同时存在“只看自己”的角色记录和主管角色的空 `FDATARULE` 记录；必须把所有角色合并后判断。
- `AR_SumReport` 若没有角色查看数据规则，且 `T_BAS_RPTDATARULECONFIG` 没有该报表的客户映射，不能把 `BD_Customer` 的规则当作该报表的保护边界。

## 官方依据

金蝶云产品手册《数据权限》：
https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E6%9D%83%E9%99%90

关键要点：数据规则默认只对单一对象有效；基础资料联动需要在数据规则选项中开启并配置受控业务对象；报表还有独立的基础资料数据权限选项。

## 结论与修复边界

- 普通销售员：移除不必要的主管/总监角色，或把目标单据/报表的查看权限改为当前销售员数据规则。
- 确实是主管：保留主管角色，但把销售组、销售员和跟单范围明确到业务要求，确认 OR 条件是否过宽。
- 不要直接改 SQL 权限表或业务表；先在金蝶权限界面调整，退出账号重新登录后，用一条属于其他销售员的客户做回归验证。
- 自建页面若直连 K3 SQL，不会自动继承金蝶数据权限；必须在服务端按会话对应的销售员/客户范围过滤，不能只靠前端筛选。
