# 工序汇报下推的状态门槛

适用于从包装入库汇报补做测试/分选汇报时，`DynamicFormService.Push` 被金蝶业务插件拒绝的情况。

## 已验证的行为

- 下推不仅检查前序工序是否有汇报，还检查目标工序分录状态、生产订单状态、作废/汇报方式、工作中心权限等条件。
- 本账套一次实测：`FOperStatus=5` 的测试分选计划可以正常 Push；`FOperStatus=6` 的代表计划被插件拒绝，返回的条件包括“工序计划对应分录状态为下达、开工或完工，且上个工序已经汇报”。
- 项目状态表只可靠记录了 `1–4`；`5/6` 的含义不能仅凭历史脚本或其他单据映射推断。未验证的状态码保持原码展示。

## 处理顺序

1. 先按精确计划号重新查询工序计划和工序汇报的所有状态，确认包装目标数量、前序汇报和当前测试汇报状态。
2. 按 `FOperStatus` 分组；先用一张代表单做标准 Push 探测，不要直接批量。
3. Push 成功的组，按工序汇报补做流程处理；Push 被插件拒绝的组立即停止。
4. 对被拒绝的组，先查标准的状态恢复/业务操作及其影响范围；未得到业务授权前，不反审核、改工序状态、直接 Save 或 SQL 写入来绕过校验。
5. 若 Push 已部分生成草稿，先按返回的真实 FID 逐张 View，确认来源计划和工序；只删除本次生成的非目标空草稿。中断后重新读取 C/A/Z 状态，已完成跳过、已有目标草稿续处理，不重复 Push。

## 记录与验收

记录每组的代表计划号、`FOperStatus` 原码、Push 结果和金蝶原始错误文本。最终验收仍需逐条核对：测试汇报恰有一张且为 `C`、`FQuaQty/FFinishQty` 等于对应包装已审核分录合计、测试台账同步、无本次遗留的 A/Z 空草稿，且包装及其他已有汇报未被修改。
