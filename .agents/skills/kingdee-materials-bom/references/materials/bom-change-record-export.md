# K3 BOM 修改记录导出

适用于 PDFN 系列或其他 `ENG_BOM` 批量修改后的留痕和 Excel 交付。

## 数据来源

- 不把写入脚本日志当作最终状态；批量结束后重新通过 K3 WebAPI `viewBill("ENG_BOM", fid)` 回读当前单据。
- 明细按真实 `FID` 去重，并核对单据状态、父项、目标分录和非目标分录。
- 对每个修改对象保留：BOM 编号、FID、父项编码/名称/规格、状态、目标物料编码/规格、修改前值、修改后值。
- 对未纳入对象单独留痕，至少说明 `D` 状态、纯铜线多分录、缺少目标物料或分录结构不符合等原因。

## Excel 内容

建议至少包含三个工作表：

1. `汇总`：数据来源、筛选范围、修改数量、目标值、最终状态和操作流程；
2. `修改记录`：逐 BOM 的完整明细；
3. `未纳入范围`：排除对象及原因。

如果用户要求“只看改了什么”，主明细仍应同时保留修改前/后值，以及铝带和其他未修改分录的关键字段，避免把“只改目标分录”误解成重建整张 BOM。

## 兼容性交付

- 使用普通工作表、冻结窗格和表头样式；不要创建原生 Excel Table、嵌套 Table XML 或工作表筛选（AutoFilter）——用户要求兼容格式，避免 Excel 打开时修复提示。
- 交付前验证：修改行数、例外行数、工作表名称/维度、ZIP 无坏项、XML 可解析、没有意外 `table*.xml`。
- 最好用 LibreOffice 无头转换一次，确认工作簿可以被实际表格引擎打开。

大批量数据导出（翻页拉取、FieldKeys 预检、output/ 交付约定）的通用流程见 `../kingdee-k3cloud/references/system/bill-export-excel.md`。
