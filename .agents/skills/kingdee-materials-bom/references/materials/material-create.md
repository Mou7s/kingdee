**已验证注意：** `FCategoryID` 是物料主表字段，必须放在 Save 的 `Model` 顶层；若错误放入 `FMaterialBase`，接口可能返回保存成功并审核成功，但实际类别会落到默认值（例如 `CHLB01_SYS 原材料`）。每次建料后必须用 `DynamicFormService.View` 独立核对 `MaterialBase[].CategoryID`，不能只看脚本的成功输出。

**新建类别字段的更新清单：** 实测新建请求即使把 `FCategoryID:{FNumber:"..."}` 放在 `Model` 顶层，`NeedUpDateFields:[]` 仍可能保存成功却采用分组默认类别。新建时把 `FCategoryID` 明确列入 `NeedUpDateFields`，保存后先用 `View` 核对 `MaterialBase[0].CategoryID.Number`；若类别不符，在提交/审核前用 `Model:{FMATERIALID,FCategoryID:{FNumber:"..."}}` 与 `NeedUpDateFields:["FCategoryID"]` 修正并再次回查。类别核对通过后再提交、审核。

**根字段与子实体分步保存（2026-09-24 BQ013 成品实证）：** 若新建 Save 的 `NeedUpDateFields` 非空，不能只列 `FCategoryID`；本次只列类别时 `FMaterialGroup.Number` 未进入校验模型，触发分组条件表达式错误。首轮至少显式列出 `FNumber/FName/FSpecification/FMaterialGroup/FBaseUnitId/FCategoryID`。首轮返回成功也不代表库存、生产等子实体字段已落值：按 `View` 读取各分录的 `Id`，用 `SubHeadEntity`…`SubHeadEntity5` 分别携带对应 `FEntryId` 补齐字段；本次未在这类补齐请求中设置 `NeedUpDateFields`。补齐子实体后，再单独用 `NeedUpDateFields:["FCategoryID"]` 保存主表类别，因为子实体补齐会使类别回到分组默认值。最终先 `View` 对照所有页签，类别及属性通过后再 Submit→Audit，最后用 `View` 与 `ExecuteBillQuery` 双查状态和关键字段。不要把本次现象推定为接口保证；以逐字段回查为准。

**主档 ID 与页签分录 ID 不能混用（2026-09-29 N406000403 实证）：** `View` 顶层 `d.Id` 是物料主档 ID，保存页签时 `Model.FMATERIALID` 必须传它；`MaterialBase[0].Id`、`MaterialStock[0].Id` 等是各页签的分录 ID，分别传给对应 `SubHeadEntity*.FEntryId`。本次将分录 ID `134093` 误传为 `FMATERIALID`，接口报物料主档不存在；改用顶层主档 ID `907692` 后页签保存及后续审核通过。

**单位注意：** 账套中的 `ge（个）` 可能是辅助单位，不能同时作为基本、库存、采购和销售单位；零星件通常使用现有同类的 `Pcs` 作为系统基本单位，并在业务说明中标注按“个”计量。不要把用户口语单位直接当作内部编码，先用 View 对照同类物料。

## DynamicFormService.View 参数坑

- 正确格式是**顶层 `formid`** + `data:{Number}` 或 `data:{Id}`：
  ```js
  await c.post("DynamicFormService.View", { formid: "BD_MATERIAL", data: { Number: "N401000263" } });
  ```
  把 `FormId` 写进 `data` 里会报「表单标识为空」。
- 返回结构在 `Result.Result`，字段名不带 F 前缀（`Number`/`Name`/`MaterialBase[]`/`MaterialStock[]`…）；引用字段同时给 `_Id` 和完整对象。建料前想抄某颗料的配置，用 View 拉它最准。
- `MaterialBase[0]` 可读 `BaseUnitId.Number`；布尔标志批量核对用 `executeBillQuery` 的 `FIsPurchase/FIsInventory/FIsSale/FIsProduce/FIsBatchManage` 更直接。**`MaterialProduce[0]` 的存在只说明配了生产领料仓/仓位，不代表 `FIsProduce=true`**（DI071 全组 `FIsProduce=false` 且每条都有该行）。
- `View` 引用对象的编码键并不统一：2026-09-29 实测 `MaterialBase[0].TaxType` 使用 `FNumber`，而 `CategoryID`、`BaseUnitId`、`TaxRateId` 使用 `Number`。快照比较器应同时识别 `Number` 与 `FNumber`，避免把正确的税种值误判为字段缺失。

## 自制/代工成品：`create_material_idm.js` 通用用法

默认模板是 AD004（SOD-323 开关管），但参数可覆盖，能建任意自制成品组（ERP2 + CHLB05_SYS + 购否·存是·销是·产是 + 批号是 + 双仓位 + 完工超短收率一次写全）：

```bash
bun scripts/tools/create_material_idm.js --number NAS0050041 --name "TK1SS388" \
  --spec "SOD-523/8K盘/无/S3" --group AS005 --stock CTK10 --place 100035 \
  --unit K --category CHLB05_SYS --erp 2 --allow-same-name    # 加 --apply 才写库
```

已验证模板（除分组与仓/仓位外其余全同）：

| 组 | 业务 | 模板 |
|---|---|---|
| `AS005` SOD-523 自制成品 | 二极管/开关管 | `CHLB05_SYS / ERP2 / K / 购否·存是·销是·产是 / 批号是 PHBM004 / 默认仓 CTK10+仓位 100035 / 领料仓同仓同仓位 / 超收500·短收5 / 计划策略1 / 主产品是` |
| `BM013` TO-252 代工成品 | AP*D 系 | 同上，仓/仓位改 `CTK11 + 100051` |

坑：

- `get(flag, dflt)` 取**第一个**匹配的 flag：参数里写两次 `--number` 时用前一个，预检随即报「编码已被占用」终止；看到预检失败先核参数回显那几行，不要当成编码真被占用。
- 同型号不同盘装（3K盘/8K盘）或不同印字必然同名，需 `--allow-same-name`；脚本仍会拦编码占用与「同分组内规格完全相同」。
- 建成后与**同组最新样板**做一次逐字段 diff（除编码/名称/规格外应全等），比逐项肉眼核对快且不漏字段。

## 规格里的印字段从哪来

同批资料里**同型号的其它封装条目**是最强依据：同一批建的 PDFN5X6 条目写成 `PDFN5X6/5K盘/无/AP80P10NF+RC1+客户周期码`，则 TO-252 那条也应带档位码 `Logo+AP80P10D+RC1+客户年记周记`，不能照本组历史通行写法省掉 `RC1`。候选列 2~3 个让用户拍板后再写入；用户选定后按选定写法一次写全。

### 成对物料（-L / 不带 -L）

- **成对物料（`-L` / 不带 `-L`）**：部分芯片类物料按账套惯例必须建成两条，名称分别带 `-L` 和不带 `-L`，规格通常相同；只有用户明确说两条都建时才扩展为成对。不能因同一分组或同一规格就假设两条属性相同：分别从最接近的现有成员核对 ERP 分类、存货类别及采购/库存/生产标志。以 10104 JXW 稳压管为例，带 `-L` 的同类记录实测可为 ERP `3` + `CHLB04_SYS`，不带 `-L` 的可为 ERP `1` + `CHLB01_SYS`；开关管 `BAS21S-L JXW / BAS21S JXW`（规格取 `芯片型号 0.28*0.28`、前型号后尺寸）同为此分化模板，其余均相同（单位 `K`、仓 `CTK01`、仓位 `0`、批号是、购是存是销是产否）。同名可横跨成品与芯片两域：`BAV21W/BAV21WS` 成品在 `BD003/BD004` 存在，不代表 `10104` 芯片已建，查重必须按域分别下结论；两条均需核对并启用批号管理。反例是 10104 的 `MOS3407A / MOS3407A-L`：两条均为 `CHLB01_SYS` + ERP `1`，不能把 JXW 的差异规则泛化到所有芯片对。HXC 主芯片封装图的成对建料核对细节见 `references/materials/hxc-chip-pair-rules.md`。**用户断言「这个物料只有 `-L`（蓝膜片）料号，再建一个晶圆片」时，先按型号主段（如 `FName like '%SBD10510%'`）扫全库再回答**：同一颗晶圆常同时有新旧两对（新 `N10201xxxx` 连号对 + 旧 `102010xxx`/`102020xxx`），只看 `-L` 那一条就动手必造重码。成对已在就回「已存在」+ 料号/规格/分组/状态/建档时间表，**不做任何写入**，再问用户真正的现象（哪张单/哪道工序不对），不要顺着错误前提建料。

**连建多条的取号与回查（30107 冲切实证）**：该脚本每次运行才现取「段内最大号 +1」，所以多条必须**顺序**执行——前一条 `--apply` 落库后，后一条才取得到新号；两次 dry-run 显示同一个候选号是预期现象，不要把第一条 dry-run 预测的号显式传给第二条，更不要并行 `--apply`（两条撞同一编码，第二条在预检报占用终止）。汇总汇报时**逐条**读脚本末尾「除编号/名称/规格外的差异项数」，不要拿最后一条的 0 代表整批。该脚本写死 `SubHeadEntity2.FIsReturn=true`，样板为 false 时 diff 必然报 `SaleIsReturn` 一项差异——销否料按 11102 劈刀先例改齐（`unAudit → Save {FMATERIALID, SubHeadEntity2:{FEntryId, FIsReturn:false}} → Submit → Audit`）或至少如实点明，不要当查询异常，也不要漏报成「差异 0 项」。

**用户给「名称 + 图号 + 材质」时先按图号定位分组与旧料**：`FSpecification like '%<图号>%'` 一步同时拿到目标分组和同图号旧料（旧料规格往往只写图号、名称带供应商前缀，如 `朗诚6M2ED冲胶口凸模A / 6M2ED001` 在 30107 冲切）；带材质的规格（`6M2ED001 F10钨钢`）与只写图号的旧料是不同料，按用户要求新建为 `N<组>顺延` 独立编码，回查汇报时点明旧料未改动，不要因同图号已有旧料就自行改建为复用。

**按先例定组要把依据随结论一起给出**：定组是从先例推断的，建料汇报里直接附上依据表（同图号/同规格族命中的 编码·名称·规格·分组 各行），不要只写「按同组口径」一笔带过。**用户把整批指定到一个工序组时，同名同规格的他组现役料不拦建**：按用户指定组建，回查汇报点明他组同料编码且未改动；同名同规格跨分组并存是该账套的正常口径，不因跨组重复停手，也不删改他组旧料。**1050 框架按材质归组的完整口径**：`10501 铜镀银 / 10502 铁镍 / 10503 镍钯金 / 10504 裸铜`；`10501` 内散落的「裸铜框架KQ/LT」是历史口径，不作归组依据，同规格族先例在 10501 也不能覆盖用户对 10504 的明确指定。
