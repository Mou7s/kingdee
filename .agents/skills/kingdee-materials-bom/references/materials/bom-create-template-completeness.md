# 按参照新建成品 BOM 的完整性核对

适用：用户明确要求为具体父项新建成品 BOM、按已有 BOM 作参照，或补查简称、文件编码、工艺路线。建料本身不授权建成品 BOM；模板相似也不代替实际物料流向确认。

## 1. 写入前

1. 实时查询父项、模板 BOM、目标名下全部状态 BOM 和拟用编号，阻止重复新建。
2. View 模板完整模型，核对审核/禁用状态与每个子件实时状态；对相近产品作旁证。
3. 单独列出表头业务字段：简称、分类/用途、单据类型、分组、组织、单位、成品数量、成品率、关联文件编码、文件编码文本、默认工艺路线及其他非空自定义字段。
4. 列出所有子项业务字段：物料、单位、分子/分母、固定/变动损耗、用量类型、发料方式、工序/工序号、供应组织、生效/失效日期、超发控制及替代方案。
5. 写入字段通过代码参考、表单元数据及扩展元数据定位；View 属性名不等于 Save 字段键。标准 `FKERNELXML` 未找到自定义字段时，继续查扩展定义或用已验证列表字段，不能因映射失败而省略该字段。
6. dry-run 展示完整模型及每项与模板的差异。只写明确授权的对象与业务方向；日期、简称等差异要有说明，不凭脚本便利生成规则。

## 2. 替代关系与保存后验证

- 替代芯片不能当成第二颗必耗芯片。核对 `MATERIALTYPE`、`ReplaceGroup`、`ReplacePriority`、`MRPPriority`、`IskeyItem`、`SubstitutionId`、`STEntryId`。
- 保存后 View 核对替代行 `ParentRowId` 指向本张主料 `RowId`，不得引用模板旧行号；不能仅凭替代组相同判断关联已正确。
- 写后重新 View，并以列表独立回查编号、父项、简称、状态、路线等字段。
- 完整对比所有表头和分录业务字段，不只比较物料/数量。基础资料按真实内码/编码比较；多语言取中文值；分录按子件加项次/替代角色匹配，不能只按料号覆盖重复分录。
- 排除新单据内码、创建/修改/审核人和时间等正常差异，但保留日期、来源标识、替代关联等差异供解释。出现未解释差异就停止提交审核，报告具体字段。
- 补单字段采用 `FID` + 目标字段最小 Save，前后核对其余业务字段无变化。用户只要求核对时不写；补字段不自动授权提交审核。
- 最终实时报告状态。用户可能在前端同时修改或审核，不能沿用上轮的草稿/D 状态。

## 3. 2026-10-09 案例与证据

范围：目标 `NAZ0010261`（ZMM9V1 5%，LL-34 SL 黑色油墨），参照 `NAZ0010067_V1.0`（FID 280950）；新单 `NAZ0010261_V1.0`（FID 909215）。以上是历史定位，复用前重新查询。

已验证材料结构：主芯片 `N101030103` 1 K、玻壳 `N107010001` 1 K、端子 `N108010001` 2 K，每 1 K 成品；`N101030104` 为替代芯片，方案 `SUB000018`。三个其他 SL 黑色油墨 BOM 没有单列油墨，这是账套参照事实，不证明油墨无成本或所有黑色油墨产品材料必然相同。

首次建单只验证材料结构，遗漏简称和默认工艺路线，文件编码由用户补填；因此不能把当时“材料回查一致”当成整张完整。

| 关联文件编码 | `F_UNW_Base_uky` | `玻封(LL-34)-TK-WI-0106-01` |
