# 物料主数据字段修改（规格型号 FSpecification 等）

## 适用

用户给截图或口述要求改某个料号的规格型号文本：追加丝印「带点」说明、改封装/包装/环保/丝印分段。改名称、分组、单位同理，但一律走最小字段 Save。

## 步骤

1. **不要用截图 OCR 定稿**。先按编码取账套里的精确原串：
   `api.executeBillQuery("BD_MATERIAL", "FNumber,FName,FSpecification,FDocumentStatus,FForbidStatus,FMasterId,FMaterialGroup.FName", "FNumber='<编码>'", 50)`。
   同一 `FName` 常有新旧两条料号（新料 N 开头、旧料不带 N），必须按用户点选的那条编码定位，不要按名称定位。
2. 截图只用来确认「哪一行、哪一列」。`vision_analyze` 的 region 必须落在图片真实像素内（越界时错误信息会返回真实尺寸，如 1376x78），一行高的窄图按整行裁切读。用户画的**红框/红字先用像素颜色定位再读字**：取彩色像素做 bbox 与颜色计数，若整块只有一种纯色、且上下边缘各两三行连续着色，说明用户只画了框、根本没有手写内容——`vision_analyze` 会把纯色矩形描述成「橙红色手写批注」并随之编出账套里并不存在的文字（幻觉），因此批注文案只能来自放大裁切后的逐字阅读，最终值仍以账套原串为准，也不要把幻觉出的批注当事实复述给用户。
3. 规格串混用 ASCII 单引号 `'`、全角 `’`、全角括号，肉眼与 OCR 都会读错。写回时 `--spec`/`--expect` 一律用**双引号**包住，不要用单引号（串内 `'` 会截断 shell 参数）。
4. 追加类注释**先查厂内既有口径，不要自创措辞**：`FSpecification like '%带点%'`，另试 `%有点%`、`%上方%`、`%下方%`。历史写法如 `首字母下方带点`、`首字母下面带点`、`“S”下带点`、`数字5下面带点)`、`字母Y平放并且底下带点`。同一单元格内已有的引号风格优先沿用（该格用 `’W’`，追加也用 `’W’`，不要改成全角 `“”`）。
5. 写入用现成脚本，默认 dry-run：
   `bun scripts/tools/update_material_spec.js --number <编码> --spec "<新规格>" --expect "<当前规格>"`（先不加 `--apply`）。
   该脚本自带：旧值守卫（当前值 ≠ `--expect` 即停）、目标规格检索（用于识别同物重复，不因规格相同而阻断）、UnAudit(C→D) → Save（仅 `FSpecification`）→ Submit → Audit → `executeBillQuery` + `View` 双通道回查。
6. 目标串存在两种合理措辞时，用一次 `clarify` 把两个完整候选串摆出来让用户选，选定后再 `--apply`；不要自行挑一种就写进生产主数据。
7. 改完确认 `FDocumentStatus=C`、`FForbidStatus` 未变、名称与分组未变；需要更强证据时重新登录再查一次（独立回查）。

## 坑

- **外购物料规格不带 27R（2026-10-19 用户纠正）**：用户明确说明“外购的没有27R”。维护已确认的外购物料时，不套用自制料的 `(27R)` 封装后缀。此次仅对用户截图指定的 `NDA0260069 / SMAJ400A` 将 `SMA(27R)` 改为 `SMA`；经默认 dry-run、前值守卫及最小字段 Save 后，View 与 ExecuteBillQuery 回查均为 `SMA / C / A`，名称与分组未变。本口径不授权批量修改其它料号，也不能仅凭编码推定所有物料的采购属性。证据：本次用户截图及 WebAPI 双通道回查（2026-10-19）。

- 名称缺少封装时，先区分列表显示与主数据缺项，再查建料报文和创建/修改时间；不能仅凭修改人认定谁删除了封装。2026-10-14 实查 `N103010008`～`N103010011` 的 `FName` 均为「黑胶」；`scripts/scratch/2026-09/mat-cel1702-create.js` 明确以「黑胶」创建 `N103010009`，证明该条建料时未带封装。另两条的创建/修改时间只相隔数秒，但这不能证明其原始名称。此次按内码/编码查 `T_BAS_OPERATELOG` 无匹配记录，不能据此断言从未改名。沿用模料模板时应单独核对名称的适用封装；胶型号和尺寸不能直接推导唯一封装，补名称须有业务依据与明确授权。

- 只改用户指的那一条料号。同名、同丝印的其它料号即使规格几乎一样也不要顺手一起改，除非用户明确说都改。
- Save 的 `NeedUpDateFields` 只列要改的字段，整单回写会覆盖名称、分组等未核对的字段。
- **规格允许相同（2026-10-16 用户明确纠正）**：不同型号、不同物料可以使用相同规格。目标规格检索仅作提示，不能仅凭规格相同阻止创建或修改，也无需为此另行请求许可。只有结合名称、型号、分组及实际业务确认是同物重复时才处理重复风险。此前“规格串不允许重复”的说法错误，已失效。NAZ0050092（BZX854B2V4）补为 `SOD-523/8K盘/无/Z1`，即使 NAZ0050004（TKBZX584C4V7）规格相同，也不构成拦截理由；依据为本次用户直接确认。
- 反审核 → 保存 → 提交 → 审核 全链路都算写入：任一环节状态不在 C/D/B 就停下如实报告，不要扩大到别的单据或改数量。
- **改单个字符要逐码点对比**：把印字后的 `’` 换成 `.` 这类一字符替换，改完把改前改后都转码点（`[...s].map(c => c + "=U+" + c.codePointAt(0).toString(16))`）逐位比对，正常只应有一个码点不同。`’`(U+2019)、`.`(U+002E)、`·`、全角/半角引号肉眼与 OCR 都近似，「回查字符串看起来对」不算证据。
- **同型号常有两条料号**：同一 `FName` 可能一条规格干净、一条带括号说明，同组兄弟料的写法也不统一。只改用户指的那条，并在报告里点明另一条的存在与写法，由用户决定要不要统一，不要顺手改齐。

## 允许采购开关（2026-10-20 实证）

- 用户按料号要求可采购时，修改的是物料基本页签 `IsPurchase`，不是人员权限；先 View 核对主档 Id、MaterialBase 分录 Id、当前开关和审核状态。
- 本次最小 Save 使用 `Model:{FMATERIALID:<主档Id>,SubHeadEntity:{FEntryId:<基本页签Id>,FIsPurchase:true}}`，不设置 NeedUpDateFields。显式设置 `SubHeadEntity.FIsPurchase` 或 `FIsPurchase` 更新清单时，本次均返回成功但 View 开关仍 false；不能以保存成功认定生效。去掉清单后 View 确认 true，再提交审核。
- 按 C→反审核→最小 Save→View 验证→提交→审核执行；恢复后列表 FIsPurchase 与 View 双查，同时核对 ERP 分类、名称、规格及禁用状态。开关变更不授权改变 ERP 分类或其他物料。
- 当次范围：NAZ0010138（ZMM2B4 2%）、NAZ0010020（ZMM2V4 5%），均由 false 改 true，最终 C/A，ERP 分类仍2。证据：`scripts/scratch/2026-10/enable-purchase-naz.js`、`output/enable-purchase-naz-20261020.json`。状态仅为当次结果，复用前实时查询。
