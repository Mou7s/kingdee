## 何时用

- 用户问「某型号蓝膜 BOM 有没有问题」、蓝膜发料/子件对不上，或要盘一遍蓝膜 BOM 的配对与重复。
- 建完晶圆对后确认蓝膜 BOM 是否已建：父项 = 带 `-L` 蓝膜片、子项 = 同名裸名晶圆片、用量 1:1、单位 `K`、分组 `0-lm`、状态 `C`。

## 第一步：先核现状，不要急着建料

用户说「这个物料只有蓝膜片料号，帮再建一个晶圆片料号」时，先查三步再回答：

1. `FNumber = '<给定料号>'` 精确定位（拿名称、规格、分组、状态）。
2. `FName like '%<型号主段>%'` 查全型号——新料与旧料会同时出现：新组 `102011 N客供晶圆片` / `102012 N客供蓝膜片`（编号常连号、`-L` 在前），旧组 `10201 客供晶圆片和蓝膜片` / `10202 客供蓝膜片`（`10202xxxx` 蓝膜片 ↔ `10201xxxx` 晶圆片 同尾号）。`FSpecification` 一般查不到（规格栏只有尺寸），别用它下结论。
3. 对该 `-L` 料号查 `ENG_BOM`（**任意分组**，不要只查 `0-lm`）确认蓝膜 BOM 是否已建。

实测结论：多数「只有蓝膜片料号」的说法在账套里是**两条都早已存在**（连号成对、均已审核）且 BOM 已建，旧料也另有一对。此时只报现状、给出料号表，不建任何料；用户确认后即可直接复用（如委外订单发料）。

## 第二步：SQL 数据路径与列名坑

| 对象 | 表 / 列 |
|---|---|
| BOM 头 | `T_ENG_BOM`：`FMATERIALID` 父项、`FGROUP` 分组、`FDOCUMENTSTATUS`、`FCREATEDATE/FAPPROVEDATE`、`FCREATORID/FAPPROVERID` |
| BOM 子项 | `T_ENG_BOMCHILD`：**子项物料列是 `FMATERIALID`**（`FMATERIALIDCHILD` 是 WebAPI `View` 的键名，写进 SQL 报 Invalid column name）、**子项单位是 `FUNITID`**（没有 `FCHILDUNITID`）、用量 `FNUMERATOR`/`FDENOMINATOR`、主键 `FID`+`FENTRYID` |
| BOM 分组 | `T_ENG_BOMGROUP` + `_L`：蓝膜现用 `0-lm`（FID 274203）、历史 `lm（旧）`（FID 117617）。**只查 `0-lm` 会把旧组数据整批漏掉** |
| 制单人/审核人 | `T_SEC_USER.FNAME`，`FCREATORID`/`FAPPROVERID` 对应 `FUSERID` |
| 委外用料清单 | `T_SUB_PPBOM`：`FSUBBILLNO` = **委外订单号**、`FMATERIALID` 父项、`FBOMID` → `T_ENG_BOM.FID`；子项在 `T_SUB_PPBOMENTRY`：`FMATERIALID`、`FMUSTQTY/FBASEMUSTQTY` 应发、`FNUMERATOR/FDENOMINATOR`、`FSEQ` |

- `SUB_PPBOM` **没有 `FMOBillNo`**（那是生产 `PRD_PPBOM` 的字段；写进 FilterString 报「元数据中标识为FMOBillNo的字段不存在」），也没有 `FCUSTOMERID`；分录**没有 `FQTY`/`FPICKEDQTY`**，领料/选单占用在 `T_SUB_PPBOMENTRY_Q`、`_C`。
- BOM 的制单人常是集成账号（`kingdee`）——批量导入的那批为同一时刻成片落库，与手工单要分开说。
- 全量拿不到时按 `ORDER BY FCREATEDATE` 一次取全再在 JS 里判，比多次带条件查询可靠。

## 第三步：配对判据（单一判据必假报）

按顺序判定，命中即「正常」：

1. **旧组配对**：父/子料号去掉非数字后等长、且**仅第 5 位数字不同**（`10202↔10201`、`10102↔10101`）→ 正常。旧组用的是通用名（`客供芯片-蓝膜片/客供芯片-晶圆片`、`稳压管芯片[2V0S-L]/稳压管芯片[2V0S]`），名称本来就不一样，不能据名称报异常。
2. **名称规范化后比较**：去全部空白（含全角空格）、去 `（禁用）/（停用）/(晶圆）`、**去掉名称中所有 `-L` 子串（不只是尾部——`三极管BC807S-L  YW` 这类 `-L` 夹在厂家后缀前）**、转大写，再比较父项（去 `-L`）与子项；允许子项 = 父项 + 厂家后缀（`SK/KXW/XS/JJ/YW/ZWJY` 等）。
3. 都不命中 → 记为**疑似错配**：父项与子项不是同一颗 die。

不要使用的判据及其失效方式：

- **只看名称严格相等**：把同一颗 die 的 `JMT10N10AJ -L` vs `JMT10N10AJ `（尾空格）、`1SS187S-L SK` vs `1SS187S`（厂家后缀只在父项）、`JY-EJ035X-3U20P-L（禁用）`、`8H007051T-36-L(晶圆）` 全部误报。
- **只看规格一致**：旧组父项规格带 `-L`（`2V0S-L`）而子项不带，成批误报；`0.624*0.583(JMT3402A-B)` 这类 `-B` 双芯差异也只是变体写法。
- **只看料号是否相邻/相差 1~2**：真正的错配两条料号常常正好相邻（`…1334-L` 配了 `…1332`、`…1418-L` 配了 `…1417`），只按料号判会漏。

判据组合后蓝膜 BOM（`0-lm` + `lm（旧）`，约 2200 行）里真正的错配只有个位数，多为「子项挂成了另一颗芯片」并伴随正确的伙伴料存在（但可能已被禁用 `FFORBIDSTATUS=B`）。

## 第四步：重复 BOM 的判读

同一父项挂 2 张 BOM 是历史常态，要分开两类：

- **两张同子项**：纯重复（常是同日隔十几分钟又建一张），版本号 `_V1.0`/`_V1.1`；只影响「取哪张」，不动数据也可以。
- **两张不同子项**：真冲突（一张对、一张错），必须让用户拍板保哪张，不能自行选。

报告时给出：父项、子项、分组、状态、建档时间、制单人（区分集成账号与手工），并按年/月给出分布——用户很可能先问「什么时候建的」。

## 第五步：委外用料清单是否按 BOM 展开

蓝膜片在委外订单里发料时，子件应与 BOM 一致。核对口径：

- 按 `T_SUB_PPBOM.FSUBBILLNO like '%<委外订单号>%'` 取该订单的全部用料清单（一单多张，一行产品一张，`FBOMID` 应指向该产品的蓝膜 BOM）。
- 逐张比 `T_SUB_PPBOMENTRY`：子项 = 裸名晶圆片、分子/分母 = 1/1、单位 `K`、`FMUSTQTY` = 委外订单行数量、头 `FDOCUMENTSTATUS='C'`。
- 相符即结论「BOM 与用料清单都正确，问题不在 BOM」，再问用户看到的具体现象（哪张单/哪道工序数量不对）后按单号往下查。

## 输出要求

- 报异常条数前必须先做上述复核；把「疑似」和「已验证」分开写，误报要说清是哪条判据造成的。
- 每条异常列：BOM 编号、分组、父项/子项（含名称与规格）、子项状态/禁用、建档与审核时间、制单人/审核人。
- 单独写明被问的那个型号**是否命中**异常。
- 修 BOM 属于写操作（改子项 = 反审核 → Save 改子项 → 审核；删多余版本 = 反审核 → 删除），必须逐条拿到用户确认后再动，不批量套用。

## 未使用的重复晶圆、蓝膜对清理

用户明确要求“没用过的直接删掉”时，授权仅覆盖当前讨论型号中实时证实未使用的重复档案，以及该对自身未被引用的蓝膜 BOM。不得扩大到在用物料、其他型号或业务单据。

1. 实时按编码获取物料内码与状态；名称、尺寸相同不等于未使用，列表“已使用=否”也不能代替业务引用检查。
2. 先通过 WebAPI 查库存和任意分组的父项、子项 BOM，再按数据库已存在的数值型物料引用字段检查采购、销售、库存历史、受托、生产、工序、委外、应收应付等业务记录。零库存不等于未使用；草稿引用也阻止清理。
3. 检查其他基础资料、自定义表与目标 BOM 的 `FBOMID` 引用；物料本身的扩展资料记录不能直接当成业务使用记录。只读检查失败或存在无法解释的引用时停止，不能将失败当零引用。
4. 若唯一关联就是该对自身的蓝膜 BOM，且 BOM 没有业务引用，先保存三份 View 快照；默认 dry-run，显式 `--apply` 后按“BOM反审核→删除→蓝膜物料反审核→删除→晶圆物料反审核→删除”逐项执行。只走 WebAPI；接口引用校验拒绝时停止，不绕过校验或 SQL 删除。
5. 每一步独立回查，最终用 WebAPI 与数据库确认目标物料、BOM 均消失，并核对保留物料与所有关联 BOM 的状态及父子项未受影响。部分成功时报告已完成范围与残留状态。

2026-10-13 已验证案例：`MTA058P03` 旧对 `N102012161/162` 有采购、入库、应付、生产及委外引用，保留；新对 `N102012228/229` 没有上述业务记录或库存，只有自身 BOM `N102012229_V1.0`，三项按上述顺序删除后经接口和数据库回查确认。现状仅代表该日，不得据此判断其他料号未使用。

证据：`output/unused-pair-N102012229-1791871867981.json`（删除前快照与操作结果）；一次性参数化预检/执行脚本 `scripts/scratch/2026-10/delete_unused_material_pair.js`。该脚本检查主要业务表与 BOM 引用；其他基础资料/自定义引用须先另行只读调查，不是全账套引用检查的替代品。
