# PDFN 铜线批量修改边界与验证清单

适用于 PDFN3、PDFN5 等产品族在 `ENG_BOM` 中按用户确认的铜线目标值批量修改。

## 目标分类

- **标准一对一**：恰好 1 条“铝带”且恰好 1 条“铜线”。用户只授权铜线时，仅该铜线分录是写入目标，铝带和其他子项保持原值。
- **纯铜线**：没有铝带但有铜线。可能有“大用量 + 标准小用量”两条同名铜线；不能看到小用量就默认唯一目标，必须确认具体 `FEntryID`。
- **其他结构**：无铜线、重复分录或分录数量不符合，单独列出，不自动批量修改。

## 状态与前值

1. 先查询 `BD_MATERIAL` 的单芯父项，再查 `ENG_BOM` 全状态，按 `FID` 去重并逐张 `viewBill`。
2. 写入批次要明确断言：父项范围、分录数量、旧铜线用量和 `FDocumentStatus`。
3. 默认批量只纳入状态 `C` 且旧用量精确匹配的标准一对一 BOM；`D`（重新审核）不能无条件并入，单独报告。
4. 纯铜线多分录即使其中一条恰好等于标准旧值，也要先确认目标分录；未确认时不改。

## 只改铜线的 WebAPI 流程

对每张已审核标准一对一 BOM：

1. 实时保存修改前快照，包括完整分录数量、物料、规格、单位和用量。
2. `unAuditBill("ENG_BOM", [fid])`。
3. `DynamicFormService.Save` 只提交：

```js
{
  FID: fid,
  FTreeEntity: [
    { FEntryID: copperEntryId, FNUMERATOR: targetQty },
  ],
}
```

4. 保存后立即回查：目标铜线等于目标值；铝带及所有非目标分录与快照一致。
5. `submitBill("ENG_BOM", [fid])` → `auditBill("ENG_BOM", [fid])`。
6. 再次回查状态 `C`、目标铜线和全部非目标分录。

## 批量停止条件

- 实时目标数量与用户确认数量不一致；
- 任一张前值已变化；
- 保存后目标值不符；
- 非目标分录发生变化；
- 提交或审核失败。

遇到失败立即停止，不跳过继续；已反审核的当前单据尝试恢复为已审核并记录恢复结果。批次结束后再次全量回查目标计数、状态、目标值和排除项。所有写入走 K3 WebAPI 单据流程，不用 SQL `INSERT/UPDATE/DELETE`。
