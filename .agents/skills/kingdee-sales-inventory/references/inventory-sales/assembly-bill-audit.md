# 组装拆卸单：查询配方与滥用诊断

用于「组装单开得太多」「账实靠组装凑」「流程单和单据对不上」这类问题的取证与诊断。一次性探针脚本放 `scripts/scratch/YYYY-MM/`，只读、无 `--apply`。

## 1. 表单与字段键

- FormId `STK_AssembledApp`（组装拆卸单）。`STK_AssemblyAppEntry` 是**组装申请**分录，不是这张单，别混。
- 表单类型 `FBillTypeID` 常见 `ZZCX01_SYS`；事务类型 `FAffairType`：`Assembly` / `Dassembly`（2026-10-29实时元数据纠正）。
- `viewBill` 分录属性名：成品 `ProductEntity`，子件 `STK_ASSEMBLYSUBITEM`；子件字段带 `SETY` 后缀。
- `executeBillQuery` 用**平铺键，不带实体前缀**：

  ```
  FID,FBillNo,FDate,FAffairType,FDocumentStatus,FNote,FAmount,
  FMaterialID,FQty,FMaterialIDSETY,FQtySETY
  ```

  写成 `FEntity.FQty`、`FProductEntity.FQty`、`FSubEntity.FQtySETY` 都会报「元数据中标识为…的字段不存在」并中断整条查询。
- `FMaterialID` / `FMaterialIDSETY` 返回内部 ID（数字），按批 join `BD_MATERIAL` 解码成 `FNumber`/`FName`/`FMaterialGroup.FNumber`，每批 ≤400 个 ID。
- 不要用物料编码组合代替分录主键。表单元数据验证的物理键为：成品 `T_STK_ASSEMBLYPRODUCT.FENTRYID`，子件 `T_STK_ASSEMBLYSUBITEM.FDETAILID`；子件通过 `FENTRYID` 关联成品行。按单据计数用 `FID`，按成品行计数用 `FENTRYID`，按子件明细计数用 `FDETAILID`。`FID + FMaterialID + FMaterialIDSETY` 会把同一成品行下相同物料的多条子件行合并。

  已验证例子：`ZZCX013300` 的成品数量为 15，同一子件物料拆成数量 3 和 12 两条明细。按物料编码组合去重会漏掉其中一条，并错误报出数量不等。取 View 时保留 `ProductEntity[].Id/Seq` 和 `STK_ASSEMBLYSUBITEM[].Id/Seq`；SQL 只读核对时按成品 `FENTRYID` 关联子件，并保留每个 `FDETAILID`。

  数量核对先按成品行和子件物料汇总拆分明细，使用基本数量并确认基本单位相同。单一子件物料且同基本单位时，才可直接检查汇总子件数量是否等于成品数量；多个不同子件物料应按 BOM 用量比例核对，不能把不同物料数量相加后与成品数量比较。

## 2. 诊断口径

一条查询拉全量分录，按真实产品/子件分录分类，出六个描述性指标；名称、分组和数量差异都要结合 BOM 与实物流复核，不能单独据此定性误用：

| 指标 | 判定 | 含义 |
| --- | --- | --- |
| 同型号换料号 | `成品FName == 子件FName`（比对前删掉所有空白字符） | 可能是料号迁移或等级拆料号，需结合 BOM 与实物流核实 |
| 跨型号转换 | 名称不同 | 描述成品与子件不同；可能是正常组合，也可能是型号转换，不能单独定性 |
| 跨分组 | 名称不同且 `FMaterialGroup` 也不同 | 优先核对 BOM、单据目的和实物流；分类差异本身不是误用证明 |
| 数量比例待核 | 汇总同一成品行下相同子件物料的拆分明细，并确认基本单位 | 对照 BOM 用量；直接比较 `FQty` 与单条 `FQtySETY` 会把拆分行及正常多子件结构误判 |
| 金额为 0 | `FAmount == 0` | 作为成本字段核查信号；需结合成本口径确认影响 |
| 无备注 | `FNote` 去空白后为空 | 事后无法追因 |

按月出「总行数 / 跨型号行数」的双列趋势，比只看总量有用——总量涨可能只是业务量涨，跨型号占比涨才是流程在恶化。

## 3. 常见误用与替代方案

组装拆卸通常用于实物组合/拆分；入错料号应优先纠正源头。已形成复杂下游、需保留原业务链的同物实物 1:1 料号更正，可评估一次性拆卸承接库存成本（见下方例外），不得一概断言必须有 BOM 或一概禁止。下列诉求优先按源业务处理：

| 真实诉求 | 正解 | 误用错在哪 |
| --- | --- | --- |
| 订单没做完、实际做成了别的型号 | 订单变更/结案到实际数，别的型号**单独开生产订单** | 全做完入库再组装转换 → 订单物料 ≠ 实物，流程单（按订单/工序计划打印）必然对不上 |
| 一批投入同时出两种产物 | 生产订单的**联产品/副产品**分录，一次投料、同时汇报入库、成本按比例分摊 | 拆成「先全做 A 再转 B」→ B 没有工单、没有工序、没有用料 |
| 等级/精度（2%、5%、HL/J06/SL） | 物料**辅助属性/等级**，一个料号 | 拆两个料号再组装互转 |
| 客户指定料号 | **客户物料编码**字段 | 新建物料再组装互转 |
| 旧料号升新料号 | 物料编码一次性升版 | 每个批次都开组装单 |
| 入错料号纠正 | 反审核/变更源头单据 | 事后组装单抹平，原始错误留在链上 |
| 盘点账实差异 | **盘点单** | 组装单平账 → 损耗原因被抹掉，良率问题查不出来 |
| 测试/分选损耗 | 不良品入不合格品仓 → 返工或报废出库，留痕 | 凭空少一截或凭空多一截 |

## 4. 堵口子的顺序

1. 对已确认是 1:1 单一物料转换的场景，可阻止汇总后的子件数量与成品数量不等；其他组合按 BOM 用量比例校验，不要全局拦截 `FQty != FQtySETY`。
2. 事由必填 + 分类下拉（料号迁移 / 盘点 / 纠错 / 其他），否则事后无从追因。
3. 跨型号组装必须关联一张生产订单，否则不给审核——B 没有工单就不许入账。
4. 盘点差异一律走盘点单。
5. 日监控三个指标：组装单量、跨型号占比、数量不等占比。
